# Odds Observer Windows ローカル版

ZIPを展開し、`Start-Local.cmd` をダブルクリックします。中央と地方の収集、PC内の表示サーバーを起動し、ブラウザーで地方のライブを開きます。ZIP版には Windows x64 用 Node.js 24 が入っています。ソースから起動する場合は Node.js 24 が必要です。

- 画面は [http://127.0.0.1:8787/](http://127.0.0.1:8787/) です。同じランチャーをもう一度開くと起動中の画面を開きます。
- 停止は起動ウィンドウで Ctrl+C。先に起動した個別の収集・送信プロセスがあれば、切り替え前に停止します。
- 締切前10分は約5秒間隔で取得します。地方は予定締切が最も近い1場を、締切前5分から2秒目標に切り替えます。中央・地方ともに対象レースを自動で切り替えます。画面は約1秒間隔でPC内のデータを読みます。
- 地方の直前5分を1秒目標で試す場合は `Start-Local.cmd --nar-final-interval 1`、全区間を10秒目標にする場合は `Start-Local.cmd --interval 10 --nar-final-interval 10`、収集せず既存データを見る場合は `Start-Local.cmd --serve-only` を使います。
- データは展開先の `data` に作成します。従来のフォルダーから起動すればその中の `data` を使用します。別の既存フォルダーを使うときは、起動前に `ODDS_DATA_DIR` にそのパスを指定します。
- 収集と新しい履歴の保存はPC内で行います。中央の公開済み過去ログは参照できます。ZIPに生データ、過去ログ、秘密情報は含まれません。

## 過去ログの着順と最終オッズ

ローカル版を収集モードで起動すると、保存済みレースを定期確認します。公式の成績に払戻金が掲載され、別の単複ページが「最終」を示した時点で、着順と最終オッズを保存します。未掲載のレースは間隔を空けて再試行します。取得済みのレースは再起動後も保持します。

「過去ログ」では、着順と選択中の券種の最終オッズを独立した列に表示します。複勝は最終オッズの範囲です。列見出しで並べ替えられ、オッズの小さい順が人気順になります。複勝は選択中の下限・上限で比較します。締切前の推移とトレンドは従来どおり受信済みの値で計算します。新しい結果データは `data/race-outcomes` にPC内保存します。 [JRAのレース確定](https://www.jra.go.jp/keiba/rules/kakutei.html) · [地方競馬の最終オッズについて](https://www.keiba.go.jp/qa.html)

古いローカル過去ログを一度だけ補うには `node --dns-result-order=ipv4first src/cli.mjs backfill-results` を使えます。競走不成立など、通常の成績・払戻を確認できない場合は取得待ちのまま表示します。

## 取得周期の実測

2026-11-07 の帯広ば12Rで、通常の地方コレクターを一時停止し、公式の単複ページだけを約1分間、1秒を目安に順次取得しました。HTTP応答を待ってから次を開始し、遅れた枠は飛ばしました。

| 比較 | 結果 |
| --- | --- |
| 1秒を目安に取得 | 61回中61回を解析。受信時刻は20:26:34.283〜20:27:34.874 |
| 同じ記録の5秒枠で比較 | 12回。単複の価格状態は両系列とも3種類 |
| 1秒側で早く見えた価格変化 | 2回でそれぞれ3.210秒、4.708秒 |
| HTTP応答と時刻表示 | 応答時間の中央値0.525秒、p95 1.651秒。発表表示は20:26と20:27の2種類 |

5秒枠との比較は同じ取得記録を間引いた結果です。供給元が毎秒価格を更新することや、他のレースで同じ差が出ることを示すものではありません。エラーが続く場合は間隔を空けます。403・429では該当場のオッズ再取得と地方の高速収集を少なくとも60秒待ちます。同じ場でリクエストを重ねず、別の場の応答を待たずに次の取得を行います。 [地方競馬情報サイトの利用規約](https://www.keiba.go.jp/terms.html)

別のレースで通常ランチャーも実測しました。佐賀11Rの20:31:21〜20:34:11に34回すべて成功し、受信間隔の中央値は5.184秒、p95は5.443秒でした。

### 締切前5分の集計

| レース | 単複の受信 | 価格が変わった回数 | 受信間隔 p95 | 予定締切前の最後の受信 | その値の発表表示 |
| --- | ---: | ---: | ---: | ---: | --- |
| 佐賀11R | 59回 | 9回 | 5.306秒 | 3.670秒前 | 20:37 |
| 高知12R | 59回 | 9回 | 5.855秒 | 1.061秒前 | 20:47 |

両レースとも発表表示は6種類で、発表表示が同じまま価格が変わった受信が5回ありました。帯広ば12Rの1秒試験を2秒刻みに間引くと、二つの開始位置のいずれでも2回の変化を捉え、1秒系列からの遅れは最大1.943秒でした。この範囲を根拠に、地方の直前5分の初期値を2秒としています。2秒での5分間の連続実測は次の開催で行います。

## ZIPの再作成

公式の Node.js 24.22.1 Windows x64 の `node.exe` と `LICENSE` を同じフォルダーに置き、`./scripts/package-local.ps1 -NodeDirectory <そのフォルダー>` を実行します。配布元のSHA-256を照合し、`work` にZIPを作成します。 [Node.js 公式リリース](https://nodejs.org/en/blog/release/v24.22.1)

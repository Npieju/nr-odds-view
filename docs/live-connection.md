# ライブ配信の接続

公開画面: https://npieju.github.io/nr-odds-view/
読み取りAPI: https://nr-odds-live-feed.goodthinker.chatgpt.site/api/live

収集PC → ローカルdata/live.json → 認証付きPUT → SitesのD1 → 公開画面のGET。
公開画面は1秒ごと、送信プロセスは2秒ごとに変更を確認します。元データの更新・収集周期とは別です。
原文HTML・DB・認証情報は送信しません。公開物はフロント向けの観測・変動JSONです。

## 実行

1. `node src/cli.mjs prepare-jra <current-CNAME> data/race.local.json`
2. `node src/cli.mjs watch-jra data/race.local.json`
3. 別プロセスで `node --dns-result-order=ipv4first src/relay-cli.mjs` を起動し、非表示stdinへ `{"token":"更新用キー"}` を1行渡します。

更新用キーはSitesのPUBLISH_TOKENと一致させます。リポジトリやファイルへ保存せず、環境・セッションで管理してください。
現在の送信プロセスはこの開発セッションから起動しています。PCの停止・スリープ・プロセス終了時は配信も停止し、画面が古さを表示します。
自動ログイン・OS起動時の常駐・全レースの自動予約は未設定。これは常設のクラウド収集サービスではありません。

APIのGETは公開、PUTはキー必須。CORSはGitHub Pagesのoriginのみ許可。読み取りはno-store。
未来・60秒より古い生成時刻はPUTを拒否し、すでに保存した生成時刻より古いデータで上書きしません。
D1は最新1件だけ保持。元データと観測履歴はローカルSQLiteに残します。

## APIのソース

`feed-api/worker/index.js` と `feed-api/drizzle/` が配信APIのコードとマイグレーションです。
`feed-api/.openai/hosting.json` にSitesプロジェクトIDを保持。
サイトソースの正規リポジトリへpushした状態をパッケージしてSitesから公開します。GitHub PagesのworkflowはAPIをデプロイしません。
Windows付属GitのTLS接続で障害が出たため、初回はNodeの証明書検証付きHTTPSで同じGitスマートプロトコルへソースを転送しました。証明書検証は無効化していません。

## 開催場ごとの自動ウォッチ

`node --dns-result-order=ipv4first src/cli.mjs watch-meetings`

当日の公式メニューから開催場を発見し、各場の発売締切前の最も近いレースを選択します。
開催場メニューは5分ごと、レース一覧は1分ごとに更新。締切で次のレースへ進みます。
予定発走変更がレース一覧に反映された場合は、出馬表と設定を再確認します。締切は引き続き通常即PAT規則の予定値です。
5分窓の前は30秒間隔、5分窓内は10秒間隔を目安に各場を順に取得。応答時間や通信失敗で実間隔は伸びるため取得時刻を確認してください。
5分窓より前の価格は最新値として表示しますが、変動幅の計算へ混ぜません。
馬名は独立に取得した公式出馬表から馬番で結び付けます。順位や画面の行位置で結び付けません。
公開画面は開催場タブを保持し、その場の次レースへ自動で切り替わります。選択場はブラウザ内に保存。
配信は1つのJSON内に場ごとの現在レースを保持。最終レース後はその場を終了と表示します。
日付が変わると前日の開催場・レース状態を破棄し、公式メニューから当日分を取り直して継続します。開催がない日も待機し、開催場が公開されると自動で追随します。

日付・レースID・CNAME・当日の開催場一覧は設定に固定していません。公式トップの遷移リンクをたどって取得します。
開催場の追加／削除やリンク変更は再取得時に反映。前日データを当日タブへ残しません。
日付変更中のHTTP応答も、日付を再確認してから配信します。仮想時計で2028年の日付跨ぎ・場の変更・次レース選択を一連の実行として検証しています。
この自動追随は収集PCとプロセスが稼働している間の動作です。OS再起動・PC停止からの自動起動は別途未設定です。

## 表示期間・30秒値（更新）

標準のグラフ・変動集計期間は発売締切10分前から締切までです。
次レースが選ばれた時点から最新価格の取得を行い、10分窓より前は30秒間隔、窓内は10秒間隔を目安に取得します。
画面には30秒境界時点までに受信済みだった直近の値と、現在オッズを別表示します。
45秒以上前の受信を30秒欄へ持ち越さず「—」にします。未来の受信を過去の欄へ使いません。
単複の上下限は維持します。「最大下落を観測した時刻」の列は削除しました。

### 現在値の比較

公開画面は過去区間の最大下落幅・最大上昇幅ではなく、現在値が直近の最高値から何％低いか、最低値から何％高いかを表示します。
比較に用いるのは締切前10分間のうち、現在値と同じ連続した観測区間です。比較対象が不足する場合は「—」。
30秒欄は読みやすさのための表示で、比較の計算には実際に受信した各観測を使います。複勝は画面で選んだ下限・上限に対応します。

## 履歴ページ

[履歴](https://npieju.github.io/nr-odds-view/#history)は開催日とレースを選択して、保存済みの締切前オッズを表示します。
公開APIの履歴用テーブルへ、収集PC上の観測をレース単位で保存します。締切前の受信のみを使用し、実際に収集していないレースや欠損区間を補完しません。
`node --dns-result-order=ipv4first src/relay-cli.mjs --history` を起動し、ライブ送信と同様に非表示の標準入力で更新キーを渡します。過去の保存分を送信し、以降は30秒間隔で未送信の終了レースを確認します。
各馬の「開く」でグラフと30秒値を同じオーバーレイに表示。時刻は発売締切を基準に揃え、実受信時刻・発表時刻は各30秒値の詳細に残します。

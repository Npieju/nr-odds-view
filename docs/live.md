# 締切前5分間のライブ観測

JRA-VAN不要、追加npm依存なし、Node 24。最終値を用いる機能ではありません。

## 起動

レースごとの設定を `data/race.local.json` に保存します（gitignore対象）。
以下は**架空の設定例**で、このままでは取得できません。現行公式ページからCNAMEを取得し、別途確認した出馬表・発売締切へ置き換えます。

```json
{
  "race_id": "synthetic-race",
  "race_label": "2026年11月1日（日曜）4回東京11日 11レース",
  "cname": "REPLACE_WITH_CURRENT_CNAME",
  "expected_selections": ["01", "02"],
  "roster_evidence": "独立に照合した出馬表のURL・取得時刻・raw_hash",
  "sales_channel": "実際に使う販売経路",
  "close_evidence": "このレース・販売経路の締切を確認した根拠",
  "sales_close_at": "2026-11-01T15:39:00+09:00",
  "scheduled_start_at": "2026-11-01T15:40:00+09:00",
  "interval_ms": 10000,
  "max_age_ms": 90000,
  "max_gap_ms": 30000
}
```

別々のターミナルで、リポジトリを作業ディレクトリとして実行します。

```sh
node src/cli.mjs watch-jra data/race.local.json
node src/cli.mjs serve
```

画面: http://127.0.0.1:8787 。ブラウザは1秒ごとに表示JSONを取得。
collectorは締切5分前まで待機、既定10秒間隔で単複を同時取得し締切で終了。
締切1時間以上前・締切後の起動は拒否。1回のHTTP要求は15秒でタイムアウト。
通信／解析失敗時は取得間隔を段階的に伸ばす（最大8倍）。元サイトの更新間隔・許容頻度を保証する数値ではありません。
Ctrl+Cで停止。再開すると同じレースの保存済み観測を引き継ぎます。

HTTPは公式競馬メニューに記載されたCNAMEを使用し、accessO.htmlへPOST。`probe-jra` が返すlinksから遷移先を確認できます。
自動で全レースを発見・予約する機能、締切変更の自動追随は今回含みません。延期等は設定を確認して再起動してください。
時計は実行PCの時計に依存します。購入成立や配信の即時性を保証しません。

## 集計の意味

区間は `[sales_close_at - 300秒, sales_close_at)`。判断時刻より後の受信、締切以降の受信、final/confirmedは集計から除外。
単なる5分前との差ではなく、時刻順に並ぶ二点間で最大下落・最大上昇をそれぞれ計算。
二点のオッズ、受信時刻、発表時刻を保持。複勝は下限・上限を別計算し、画面で選択可能。
同一時刻ラベル内の価格改訂も、実際の受信順の変化として記録。発表精度を秒にしない。
欠損・母集団変更・時刻逆行・取消等の区切りをまたぐ極値比較はしない。
観測が一部だけ、受信が止まった、発表が古い場合は品質表示。古いJSONを読んでもブラウザ側で停止を表示。
最大変動は観測済みデータ内の値です。ポーリング間に起きて戻った変化は検知できません。

## 配信

現状はローカルで動作。サーバーは127.0.0.1にのみ待受け、ファイル公開は画面3ファイルとlive.jsonに限定。raw/DBは配信しません。
`public/` はビルド不要の静的画面で、Pagesへ配置可能。
外部のJSON配信を使う場合は `?data=https://.../live.json` を指定し、その配信側にCORSとキャッシュ無効化が必要。
Pages/Actionsを10秒コレクターとして使用しません。collectorは独立常駐し、JSONだけを別途配信する構成です。
再配信条件の確認・実測品質の確認は未完了のため、今回実データの公開配信はしていません。

## 開催中の実測用コマンド（2026-11-07追加）

```sh
# 公式の現在の単複ページのCNAMEから設定を作成
node src/cli.mjs prepare-jra <current-CNAME> data/race.local.json
node src/cli.mjs watch-jra data/race.local.json
# 収集中・収集後の品質計測
node src/cli.mjs measure data/race.local.json
```

prepare-jraは公式オッズ見出しのレース同一性と予定発走を読み、応答内の公式出馬表リンクへアクセスして馬番を独立照合します。
通常の即PAT締切規則（予定発走1分前）から設定を作り、`close_basis=scheduled_rule_not_observed` と明記します。
これは実際の受付状態の観測ではありません。発走時刻変更はまだ自動追随しません。
measureはHTTP取得数・失敗数・解析拒否数、単複ごとの観測数・内容更新数、発表時刻と受信時刻の差の中央値/p95、最後の締切前受信時刻を返します。
内容更新数は最初の値を含めず、同じ値の再受信を更新とは数えません。発表時刻は分精度のため古さは幅で扱います。
中央値/p95は収集スナップショットで重み付けされた観測値で、公式の配信SLAやネットワーク単体の遅延ではありません。

2026-11-07東京7Rの発売中画面でパーサーが実際に成功。過去の「現行発売中ページ未取得」という記載はこのレースについて解消しました。
鮮度を超えた値も受信事実として保存・表示し、現在の鮮度不良表示を分けます。古いという理由で推移や最新価格を消しません。
現行アダプターは数値単複に限定。取消等の未知形式、別券種、他レースの画面変更まで検証済みとは扱いません。

2026-11-07の実測で、より新しい発表時刻の応答の後に、古い発表時刻・以前と同じ内容が返るケースを観測しました。
原因（配信側キャッシュ等）は未特定です。発表時刻の最大値より古い応答はDBに保存し、変動計算には使用しません。
古い応答を新しい変動の基準に戻さないテストを追加しています。同分内の改訂は順序を判定できないため受信順の観測として残します。
